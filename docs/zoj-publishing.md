## 통합 대회 등록 · 업데이트 흐름

ZOJ의 ‘Editor에서 가져오기’는 `/problems/zoj-transfer`로 연결됩니다.
대회·참가 유형을 URL로 전달하지만 이 값은 권한을 부여하지 않습니다.
Editor의 현재 로그인 계정과 ZOJ의 현재 대회 권한을 각각 확인합니다.

문제 목록에서 전송할 자료를 선택하고 검증된 ZOJ 패키지를 준비합니다.
일반 패키지 생성과 같은 `_create_job`을 사용하며 미커밋 작업 사본이
있으면 먼저 커밋하도록 안내합니다. 패키지 준비만으로 등록하지 않습니다.

문제 실행 기록과 통합 화면은 모두 같은 `ZojPublishing` 창을 사용합니다.
신규 등록은 `publish-zoj`, 업데이트는 `zoj-updates:preview`와
`zoj-updates`만 사용합니다. 기존 문제 목록은 서명된 읽기 API로 조회하고,
변경 내용·대상 해시·ZIP 해시·이유·진행 중 확인을 검증한 뒤 적용합니다.
기존 제출·판정 보존, 이전 ZIP 백업, 알림, 중복 요청 처리는 기존 수신
트랜잭션에서 수행합니다. 완료 화면에서 ZOJ 운영 화면으로 돌아갑니다.

Judge의 `editor-problems` 경로는 현재 권한 확인 후 410과 새 위치를
반환하며 패키지를 만들거나 등록하지 않습니다. Editor의 서버 간
`zoj-library`는 제거하고 로그인 세션 기반 `zoj-transfer`로 대체했습니다.
Judge는 더 이상 Editor 목록·패키지를 가져오는 전송 코드를 보유하지 않습니다.

# 폴더 정리와 ZOJ 전송

## 작업 폴더

로그인 후 문제 목록의 내 폴더에서 폴더를 만들고 편집합니다. 폴더 편집의
상위 폴더를 바꾸면 하위 문제와 폴더도 함께 이동합니다. 문제는 끌어 놓기,
행의 폴더 버튼, 여러 문제 선택 후 이동으로 정리합니다. 현재 폴더에서
만들거나 가져온 문제는 그 폴더에 바로 들어갑니다. 검색은 모든 폴더를
대상으로 합니다. 폴더 삭제는 문제를 삭제하지 않으며 내용과 하위 폴더를
상위 위치로 옮깁니다. 상위에 같은 이름의 폴더가 있으면 먼저 이름을 바꿉니다.

폴더 배치는 개인 계정에 속합니다. 공유받은 읽기 전용 문제도 자기 폴더에
정리할 수 있고 동료의 배치·공유 권한·문제 주소·리비전은 바뀌지 않습니다.
계정당 폴더 200개, 깊이 12단계, 한 번에 문제 500개를 지원합니다.

## 사용 흐름

1. 문제 변경을 커밋합니다.
2. 패키지에서 `ZOJ 문제 ZIP`과 기본 지문 언어를 선택하고, ZOJ에서 사용할
   테스트 세트를 체크합니다. 한 개 이상 선택하며 전체 선택·해제도 가능합니다.
3. `검증 후 패키지 생성`을 누릅니다. 선택한 세트와 풀이의 기대 판정 및
   checker·validator 자체 테스트가 일치해야 검증된 ZIP이 생성됩니다.
4. ZIP 다운로드로 기존 ZOJ의 문제 가져오기에 등록하거나, `대회 등록 · 업데이트`을
   눌러 같은 이메일에 문제 등록 권한이 있는 대회·참가 유형·문제 번호를 선택합니다.
5. 등록을 누르면 새 문제가 만들어집니다. 같은 번호가 있으면 중단하며,
   진행 중인 대회에는 등록하지 않습니다. 채점 번들 생성도 자동 요청됩니다.

전송은 문제 소유자만 가능합니다. 공유 편집자는 패키지를 만들 수 있으나
소유자의 계정을 대신해 전송할 수 없습니다. 전송 기록은 서버에 저장해
문제에 접근 가능한 동료도 확인합니다. 변경 후에는 새로 커밋·검증해야 합니다.
네트워크 오류 후 같은 패키지·대회·참가 유형·번호로 재시도하면 ZOJ의 DB에
저장한 전송 기록으로 중복 생성하지 않습니다. 오류 이후 다른 번호를 선택하면
별개의 등록 요청입니다.

## ZOJ ZIP의 내용과 지원 범위

기존 ZOJ의 `zoj-problem`, 버전 1, `manifest.json` 형식을 사용합니다. 지문은
ZOJ_META의 입력·출력 설명·노트·예제를 포함합니다. 이미지 참조는 asset ID로
바꿉니다. 선택한 테스트 세트·입력·정답, Main/검증 풀이, checker·validator,
testlib.h와 라이선스, 생성기 및 지원 파일을 보관합니다. 선택한 세트의 테스트를
세트 순서대로 합쳐 하나의 활성 채점 데이터로 등록합니다. 서로 같은 번호가
있어도 합친 데이터에서는 번호를 연속으로 다시 매겨 모두 포함합니다.
선택하지 않은 세트는 채점에 포함하지 않으며, 원본 Editor 작업 자료에는
세트 구성과 원본 파일을 유지해 다시 가져올 때 복원합니다. 기존 단일 세트
API로 만든 패키지의 활성·비활성 버전 방식도 계속 지원합니다.

선택한 언어는 ZOJ의 기본 지문으로 저장합니다. 본문을 작성한 다른 언어의
제목·본문·입출력 설명·노트·예제도 번역 지문으로 함께 등록하며, 참가자는
ZOJ 지문 화면에서 언어를 선택합니다. 번역 해설도 별도로 저장하고 기존
해설 공개 정책을 적용합니다. `korean`·`english` 등 언어 이름은 `ko`·`en`
코드로 변환합니다. 같은 코드에 해당하는 언어를 중복 작성하면 패키지 생성을
차단합니다. 이 기능은 ZOJ의 `0048_problem_statement_languages` 마이그레이션과
다국어 수신 기능을 먼저 배포해야 사용할 수 있습니다.

`editor-project.json`과 복원용 추가 파일은 원본 설정·자료·자체 테스트를
복원하도록 비공개 채점 지원 파일 영역에 보관합니다. 참가자에게는 이 원본
파일과 검증 풀이를 첨부 목록으로 제공하지 않습니다. 이 복원 자료는 실제
채점 실행 환경으로 복사하지 않아 채점 번들을 불필요하게 키우지 않습니다.
Editor에서 내보낸
ZOJ ZIP은 Editor의 패키지 가져오기에도 사용할 수 있습니다. 일반 ZOJ에서
내보낸 ZIP은 Editor 복원 자료가 없으면 현재 가져오기를 지원하지 않습니다.

그룹·부분 점수, 대화형 채점, 파일 입출력, 추가 validator, 풀이 결합 파일은
ZOJ에서 같은 방식으로 실행되지 않아 내보내기를 차단합니다. ZOJ checker는
C++17·C·Python 소스를 지원하며 다른 언어의 checker는 내보내기를 차단합니다. 시간 제한은
100~10,000ms, 메모리는 16~1,024MiB를 사용합니다. 압축 ZIP은 Editor의
128MiB 한도 이내여야 합니다. 설정을 조용히 바꾸거나 테스트를 생략하지 않습니다.
Editor 검증 환경과 ZOJ의 컴파일러·언어별 시간/메모리 보정은 다릅니다.
전송 후 ZOJ에서도 검증 풀이를 채점해 확인하세요.

## 서버 설정

ZOJ 백엔드의 `feature/editor-publishing` 브랜치에 전용 수신 API와
`0040_editor_problem_imports` 마이그레이션이 있습니다. 이 수신 기능을 ZOJ에
먼저 반영해야 합니다. 운영 반영은 이 기능의 개발 작업과 별도입니다.

두 서버에 같은 별도 무작위 비밀키를 설정합니다. 세션 키나 채점 노드 키를
재사용하지 마세요. 키는 서버 환경변수에만 넣고 브라우저·Git에 올리지 않습니다.

```dotenv
# ZOJ backend
EDITOR_BRIDGE_SECRET=<별도 무작위 키, 32자 이상>

# Editor API
EDITOR_ZOJ_API_URL=https://zoj.kr/api
EDITOR_ZOJ_PUBLIC_ORIGIN=https://zoj.kr
EDITOR_ZOJ_BRIDGE_SECRET=<ZOJ에 설정한 같은 키>
EDITOR_ZOJ_CA_FILE=
```

내부 HTTPS 주소도 사용할 수 있습니다. 자체 CA는 API 컨테이너의 `/certs`에
읽기 전용으로 넣고 `EDITOR_ZOJ_CA_FILE=/certs/ca.crt`를 지정합니다. 인증서
확인을 끄지 않습니다. API 주소는 서버 설정에 고정하며 사용자가 임의 URL을
보낼 수 없습니다. 운영에서는 HTTPS만 허용하고 리다이렉트를 따르지 않습니다.

마이그레이션 실행 후 API 컨테이너를 재생성해야 새 환경변수가 반영됩니다.
연동 키는 Editor API에만 주입하고 코드 실행 worker에는 전달하지 않습니다.
설정이 없으면 ZIP 다운로드는 작동하며 바로 전송 모달은 설정 필요를 안내합니다.

## 인증과 권한

Editor는 ZOJ 공통 세션으로 인증한 이메일을 서버에서 읽습니다. 사용자가
전송 요청에 다른 이메일을 지정할 수 없습니다. 전용 키로 메서드·경로·대상
정보·이메일·시각·일회용 nonce·ZIP 해시를 HMAC 서명합니다. ZOJ는 이를
검증하고 90초 시간 범위와 nonce 재사용을 검사합니다. ZIP 무결성도 검사합니다.

ZOJ는 그 이메일의 현재 운영자 계정을 직접 조회합니다. 대회 목록 및 각 등록
시 `contest.problem.manage` 권한을 확인하고, 등록 트랜잭션 안에서 운영자
행을 잠가 권한을 다시 확인합니다. 권한 회수 후 새 등록이나 재시도는 거부됩니다.
인증된 연결로도 일반 ZOJ 로그인 토큰을 발급하거나 다른 운영 작업을 할 수 없습니다.
문제·파일·전송 기록·운영 작업 로그는 같은 등록 트랜잭션에 저장합니다.

이 구조에서 Editor 서버는 검증된 이메일의 신원 발급자로 신뢰됩니다. 따라서
연동 키를 가진 서버는 다른 이메일 신원을 서명할 수 있습니다. 키를 잃으면
양쪽 키를 즉시 교체하고 접근 가능한 네트워크와 서버 계정을 제한해야 합니다.
사용자별 권한을 요청의 문자열로 신뢰하거나 전체 운영자 토큰을 공유하지 않습니다.

## 검증

SQLite·PostgreSQL에서 폴더 계정 분리와 동시 역방향 이동의 순환 방지,
전체 ZIP 무결성·Editor 복원·권한·변경된 패키지 차단을 테스트합니다.
ZOJ 수신 측에서는 서명 변조·만료·nonce 재사용·계정/대회 범위·권한 회수·
전송 재시도의 단일 등록과 운영 로그를 테스트합니다. 실제 Docker 테스트는
정답/오답 및 validator를 실행한 뒤 ZOJ ZIP을 만들고 복원합니다.
