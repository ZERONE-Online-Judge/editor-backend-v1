# Invocation과 스트레스 테스트

입력·정답 생성의 기본 범위는 화면에서 선택한 테스트 세트입니다.
테스트 화면의 **전체 테스트 세트 생성**은 모든 세트를 생성합니다.
패키지 생성은 전체 세트를 검증합니다. 실행 기록에는 실제 처리한 세트가
표시됩니다. 일반 문제의 직접 입력 기대 출력은 작성 중 참고용이며,
준비 단계에서 Validator 검사 후 Main 출력으로 교체됩니다. 대화형 문제의
Interactor 참고 자료는 대화 로그로 교체하지 않습니다.

## 생성 결과 확인과 버리기

완료된 입력·정답 생성 기록에서 테스트 번호를 선택하면 실제 입력과 정답을
바로 읽을 수 있습니다. 큰 파일은 앞부분만 보여주고, 원본 다운로드도
유지합니다. 결과를 보거나 다운로드하는 것만으로 작업 사본은 바뀌지 않습니다.

**반영하지 않고 버리기**는 내 미반영 목록에서 결과를 제외합니다. 작업
사본과 저장하지 않은 편집은 유지하고 실행 기록·생성 파일도 남깁니다.
버린 결과는 다시 반영할 수 없으며, 다시 생성하면 새 작업으로 처리합니다.
협업자의 사본이나 반영 결정에는 영향을 주지 않습니다. 이미 반영한 결과의
자료 수정은 테스트 편집 화면에서 진행합니다.

## 실행 범위

언어별 시간·메모리와 자동 보정은 **개요 > 기본 정보 > 언어별 개별 설정**에서
한 번 설정합니다. 입력·정답 생성, 전체 검증, 스트레스, 패키지 검증이
같은 값을 사용합니다. 전체 검증 화면에서 다음 실행 범위를 지정합니다.

- 내 작업 사본 또는 최신 커밋 리비전
- 전체 풀이 또는 선택한 풀이; 기대 판정은 저장된 태그 사용
- 테스트 세트와 전체·번호 범위·선택한 등록 테스트
- ZOJ 실제 채점기 고정, 개요에 저장한 공통 언어별 제한 사용
- 실행 이름과 메모

번호 범위는 `1-10, 15, 20-25` 형식입니다. 선택한 세트에 존재하는 번호만
실행합니다. 생성 스크립트로 만들 예정인 번호도 범위에 포함할 수 있습니다.
범위 검증은 선택하지 않은 테스트를 생성하거나 실행하지 않습니다.
부분 범위의 점수는 전체 테스트 점수로 표시하지 않습니다.

검수자는 **내 임시 검수 코드 실행**으로 별도 코드를 실행할 수 있습니다.
원본 파일과 다른 이름을 사용하며, 코드는 해당 실행 기록에만 보관됩니다.
임시 코드가 원본 풀이 태그나 테스트 데이터를 바꾸지는 않습니다.

## 협업 권한

| 권한 | 허용 범위 |
| --- | --- |
| READ | 문제 자료와 실행 결과·의견 열람 |
| READ + 검수자 | 커밋 리비전으로 검증·스트레스·구성요소 검증·렌더링, 임시 코드 실행, 의견 작성, 자신의 실행 취소 |
| WRITE | 작업 사본 수정·실행·커밋, 생성 결과와 반례 반영 |
| OWNER | WRITE 기능과 협업 권한·전송 관리 |

검수 실행은 커밋에 저장된 입력·기대 출력·판정 태그를 그대로 사용합니다.
작성자가 입력·정답 생성 결과를 반영한 뒤 커밋해야 실행할 수 있습니다.
검수자에게 테스트 수정이나 기대 판정 변경 권한은 부여하지 않습니다.
기존 번역 역할의 번역 지문 렌더링 권한은 유지합니다.
실행 중 검수 권한이 회수되면 작업이 중단됩니다.
의견은 실행 결과와 별도 저장되어 워커 진행 상황 갱신 후에도 유지됩니다.

## 스트레스와 반례

비교 풀이를 여러 개 선택하거나 **Main 이외 전체**를 선택합니다.
각 반복에서 생성한 동일 입력을 Validator와 기준 풀이로 확인한 뒤 모든
선택 풀이에 실행합니다. 중복 입력은 다시 비교하지 않습니다.

반복 횟수 또는 실행 시간과 횟수를 지정합니다. 한도 중 먼저 도달한
조건에서 종료합니다. 시간에는 컴파일과 채점 대기도 포함됩니다.
경과 시간·완료 반복 수·중복 수·종료 이유는 실행 기록에 저장됩니다.
중단 요청은 실행 정리까지 약간의 시간이 걸릴 수 있습니다.

첫 반례 입력의 비교를 마치고 종료하거나 서로 다른 입력을 1·5·10개까지
수집할 수 있습니다. WA·TLE·MLE·RE 등의 수집 판정을 선택합니다.
각 반례에 풀이별 판정·실제 출력·시간·메모리와 최초 반례를 보관합니다.

반례를 선택하여 원하는 테스트 세트에 일괄 추가합니다. WRITE 이상만
반영할 수 있으며 동일 입력은 중복 추가하지 않습니다. 원본 자료가 바뀐
실행의 반례는 바로 반영할 수 없으므로 최신 자료로 다시 확인하세요.
추가 결과는 내 작업 사본에 저장되며 커밋해야 공유됩니다.

## 서버 설정

`GET /api/execution-environment`는 인증된 사용자에게 실제 설정과 현재
진행·대기 작업 수를 제공합니다. 화면에 숫자를 별도로 고정하지 않습니다.

- `EDITOR_WORKER_CONCURRENCY`: Editor 동시 작업 수, 기본 2
- `EDITOR_JOB_TIMEOUT_SECONDS`: 작업 전체 한도, 기본 1,800초
- `EDITOR_STRESS_MAX_SECONDS`: 스트레스 시간 선택 상한, 기본 1,800초
- `EDITOR_JUDGE_CONCURRENCY`: ZOJ 연결 검증의 내부 동시 실행 수, 기본 3

스트레스 시간 상한은 작업 전체 한도와 스트레스 한도 중 작은 값입니다.
세트당 테스트·반복 횟수·생성기 인자·자원 한도는 실행 코드와 API가
동일한 정의를 사용합니다. 환경 설정 변경 후 API와 워커를 함께 재생성해야
표시값과 실행 정책이 일치합니다. 실행 의견 테이블은 배포 마이그레이션에
포함되므로 기존 데이터베이스에도 `alembic upgrade head`를 적용합니다.

## 스트레스 테스트의 풀이별 기록

새 스트레스 작업은 기준 풀이와 각 비교 풀이의 테스트별 판정, CPU 시간,
경과 시간, 메모리, 생성 시드·명령과 실제 입력·기대 출력·실제 출력을
서버에 보관합니다. AC와 반례 수집 대상이 아닌 판정도 기록합니다.
풀이별·전체 최대 시간과 최대 메모리는 저장된 풀이 실행에서만 집계하며,
생성기·Validator·Checker·반례 축소 시도는 포함하지 않습니다.
기준 풀이의 AC는 정상 실행을 뜻하며 그 출력을 비교의 기대값으로 사용합니다.

`stress_results`에는 풀이별 `cases`, `max_cpu_ms`, `max_memory_kb`가,
`stress_result_summary`에는 전체 최댓값·생성 테스트 수·풀이 실행 수가 담깁니다.
큰 입출력은 기존 권한 검사를 사용하는 내용 주소 기반 Blob으로 저장합니다.
동일한 내용은 작업 안에서 중복 저장·집계하지 않으며 기존 64MiB 자료 한도를
넘으면 `evidence_limit`으로 종료하고 이미 저장한 결과를 유지합니다.
대기·중복 제외·취소된 실행을 AC로 채우거나 최대 자원으로 추정하지 않습니다.
병렬 선행 실행 중 종료 시점까지 순서대로 반영된 결과만 기록에 남습니다.

이전 작업은 통과한 출력을 보관하지 않았으므로 전체 기록을 복원할 수 없습니다.
새 요청의 기록 버전을 구분하여 이전 캐시를 새 결과처럼 재사용하지 않습니다.
