# ZOJ 채점기로 풀이 검증

운영 환경의 `전체 풀이 검증`과 `검증 후 패키지 생성`은 기존 ZOJ 채점
에이전트에서 풀이를 실행합니다. 생성기·validator·기준 출력 준비·checker
자체 테스트·PDF 생성·스트레스 테스트는 Editor 격리 서비스에서 실행합니다.
기준 출력 준비에는 여유 제한을 사용하며, 최종 풀이는 문제의 제한으로
다시 채점합니다. 준비 환경과 최종 채점 환경을 결과에 각각 저장합니다.

## 지원 범위

- 표준 입력/출력, 비대화형 문제, C++17·C99·CPython 3.13·Java 8.
- ZOJ 채점기의 isolate, CPU 시간 측정, 메모리 측정 및 TLE 재확인을 사용합니다.
- 대회와 동일한 기본 언어 보정: Python 시간 `3T + 2초`, 메모리
  `2M + 32MiB`; Java 시간 `2T + 1초`, 메모리 `2M + 16MiB`.
- 원본 문제 제한은 100~10,000ms, 16~1,024MiB입니다.
- 대화형·grader·그룹/부분 점수·PE/테스트셋별 추가 태그·C++20·C17·Java 17은
  실행 환경에서 `Editor 격리 실행`을 직접 선택해야 합니다. 언어를 자동으로
  낮추거나, ZOJ 통신 오류를 Editor 실행으로 대체하지 않습니다.
- Java 8 풀이에는 패키지 없는 `public class Main`을 사용합니다.

## 처리와 기록

공통 계정의 확인된 이메일, 요청 내용 해시, 짧은 유효 기간의 HMAC 서명으로
내부 TLS API에 자료를 전달합니다. ZIP 경로·크기·개별 해시를 확인하고,
기존 채점 노드의 자격 증명 및 할당된 lease가 일치하는 결과만 받습니다.
대회 제출/재채점/검증 AI 작업을 먼저 가져간 뒤 Editor 작업을 배정합니다.
Editor 작업은 대회·제출·스코어보드 행을 만들지 않습니다.

같은 자료의 재전송은 중복 등록하지 않습니다. 같은 문제 자료는 여러
풀이 사이에 재사용합니다. 테스트 번들 다운로드가 실패하면 개별 테스트
파일을 받도록 실제 경로도 유지합니다. 빈 테스트 실행을 정답으로
간주하지 않습니다. 취소·lease 만료 후 도착한 이전 결과는 거부합니다.

자료 저장 중에는 `uploading` 예약만 만들고 실제 채점 대기열에 넣지 않습니다.
저장이 끝나면 `waiting`으로 바뀝니다. ZOJ 백엔드가 이 상태를 지원하도록
먼저 배포한 뒤 Editor를 배포하세요. DB 마이그레이션이나 채점기 교체는
필요하지 않습니다.

등록·상태 조회가 일시적인 429/502/503/504를 반환하면 같은 요청과 자료로
재시도합니다. 1초부터 최대 5초 간격으로 기다리며, API 호출별 재시도 예산은
`EDITOR_JUDGE_REQUEST_RETRY_SECONDS`(기본 120초, 최대 600초)입니다.
전체 작업 시간 한도와 취소는 대기 중에도 확인합니다. 권한·자료 불일치
등의 4xx 오류는 재시도하지 않습니다. 작업 ID를 받기 전에 응답이 끊긴
등록도 operation ID로 취소하여 나중에 중복 실행되지 않게 합니다.

채점기는 첫 실패에서 종료합니다. 실패 태그의 풀이에는 확인된 실패만
제외하고 나머지 테스트를 다시 요청하여 전체 태그 의미를 유지합니다.
Main/정답 풀이의 첫 실패, 컴파일/시스템 오류는 남은 테스트를 통과했다고
표시하지 않습니다. 각 요청의 채점 노드·버전·판정·최대 시간/메모리·원본
메시지를 보관합니다. 요청 전체의 최대 시간을 개별 테스트 시간으로
표시하거나, 전달받지 않은 출력 파일을 생성하지 않습니다.

Editor 결과는 서버에 저장됩니다. ZOJ의 임시 실행 자료는 완료 후 48시간
정리 대상으로 처리하고, 실행/대기는 1시간을 넘기면 종료합니다.

## 기대 판정 범위

풀이의 기본 기대 판정은 이번 검증에 포함된 테스트 세트의 기본 범위를
합산해 평가합니다. 기본 TL인 풀이가 `tests`에서 모두 AC이고 `tle`에서
TLE를 받으면 전체 기본 범위는 일치입니다. 세트별로 TLE를 요구하지 않습니다.
세트나 그룹에 별도로 지정한 기대 판정은 해당 범위에서 독립적으로 확인하며,
그 범위는 기본 판정의 집계에서 제외합니다.

테스트 식별자는 세트 이름과 번호의 조합입니다. 일부 테스트만 실행한
기록은 전체 기대 판정 검증을 완료했다고 표시하지 않습니다. 이전에 완료된
풀이 검증을 열면 저장된 실제 결과로 현재 기대 범위를 다시 계산합니다.
코드 재실행이나 실제 판정·시간·메모리의 수정은 하지 않습니다. 이미 만든
패키지의 검증 기록은 변경하지 않습니다.

## 배포와 확인

먼저 ZOJ 백엔드의 `0047_editor_judge_runs` 마이그레이션과 private API를
배포한 뒤 Editor 백엔드·프런트엔드를 배포합니다. 채점 노드는 기존
프로토콜을 사용하므로 이번 연결을 위해 수정할 필요가 없습니다.

`EDITOR_JUDGE_BACKEND=zoj`, `EDITOR_JUDGE_CONCURRENCY=3`이 Compose 기본값입니다.
워커 2개를 포함해 최대 6개 풀이 요청을 동시에 처리합니다. 내부 주소는
`EDITOR_ZOJ_API_URL=https://10.10.10.110:6443/api`, 공개 CA 경로는
`EDITOR_ZOJ_CA_FILE=/certs/zoj-ca.crt`입니다. 기존 공유 연결의 비공개 서명
키를 사용하며 브라우저에 전달하지 않습니다.

배포 후 `Physical Judge Integration Check` 워크플로를 수동 실행하면
기존 공통 계정을 대상으로 임시 문제 하나를 만들어 실제 워커와 채점 VM에서
C++·C·Python·Java 정답, 오답, TLE, MLE, 컴파일 오류를 확인합니다. 계정을
생성하거나 대회를 변경하지 않습니다. 임시 Editor 문제와 실행 자료는
확인이 끝나면 제거하며, 다른 프로젝트가 사용하는 공통 파일은 보존합니다.
